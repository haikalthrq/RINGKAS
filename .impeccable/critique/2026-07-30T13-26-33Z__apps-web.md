## Anti-Patterns Verdict

The product does not look like a clear AI-generated dashboard. The blue structure/orange evidence rule, flat surfaces, restrained shadows, and citation-first chat are distinctive enough. No gradient, decorative glass, or repeated dashboard metric pattern was found.

The detector completed using the installed skill path with 63 advisory findings: 45 font-size values outside the documented ramp, 17 radius values outside the documented scale, and 1 overused-font finding for Inter. These are mostly small labels, metadata, and compact controls, so they are not release blockers, but they show that the CSS has drifted from the written design tokens. The Inter finding is a warning, not a reason to replace the current typeface immediately.

## Overall Impression

The app has a credible research workspace in `/chat`, but the rest of the site has not fully adopted that product logic. Visual consistency is high at the token level and medium at the experience level. The biggest opportunity is to make every route feel like the same evidence-first tool rather than a marketing entry page plus several English-only utility pages.

## What's Working

1. `/chat` communicates the core ask -> answer -> citation drawer flow clearly.
2. Evidence states, excerpts, page metadata, and source URLs support the product promise.
3. Shared blue/orange colors, borders, focus styles, reduced motion, and flat surfaces create a calm visual family.

## Priority Issues

### [P1] Locale consistency is unfinished

Home, header, and chat support Indonesian/English, but login, register, Documents, Admin, protected errors, and 404 remain English. The root document also remains `lang="id"` when English is selected.

Why it matters: users can enter in Indonesian and suddenly switch products mid-flow; screen readers also receive the wrong document language.

Fix: use one shared locale source for every route, update document language, and expose the language control globally or define a single supported surface clearly.

Suggested command: `$impeccable harden`

### [P1] Mobile header does not match the documented system

`DESIGN.md` specifies a stacked mobile header, but `globals.css` keeps the header horizontal below 640px. Authenticated nav links can wrap while chat height assumes a fixed 64px header. The scope label collapses visually to only a dot.

Why it matters: navigation and viewport sizing become fragile exactly where one-handed use needs the clearest hierarchy.

Fix: stack brand and nav below 640px, calculate workspace height from the real header, and retain a visible or accessible scope label.

Suggested command: `$impeccable adapt`

### [P2] Account and route IA lack user control

Authenticated users have no visible sign-out or account action. Registration redirects to `/documents`, while login defaults to `/chat`. Documents is hidden from guests even though the product positioning includes finding publications.

Why it matters: users cannot predict where they land or safely end a session, especially on shared devices.

Fix: add sign-out, align post-auth destinations, and make the guest/login boundary for Documents explicit.

Suggested command: `$impeccable harden`

### [P2] Home is valid as a gateway but over-marketed

Home currently explains scope and evidence, then routes users to chat. That role is defensible for first-time and guest users, but the large 5.3rem headline, large empty space, and `01 / 02 / 03` strip read more like a generic landing page than the documented "Ruang Baca Fokus" research workspace.

Why it matters: it adds a click before the product's first-minute goal and creates a visual register different from `/chat`.

Fix: keep Home only as a first-visit gateway; reduce the hero scale, use the documented display token, replace the process strip with a compact evidence example or direct question field, and route returning users directly to `/chat` when appropriate.

Suggested command: `$impeccable distill`

### [P2] Documents and historical chat are not yet research-complete

Documents exposes only the first 20 results without pagination or URL state. Historical chat messages do not restore `source_sufficiency`, so saved answers can show unavailable status even when citations exist.

Why it matters: researchers cannot reliably continue a search or trust the historical evidence state.

Fix: add pagination or an explicit result ceiling, preserve search state in the URL, and persist/return evidence sufficiency for historical messages.

Suggested command: `$impeccable harden`

- Alex, repeat researcher: history helps, but Documents lacks pagination, URL state, sorting, and efficient result navigation; no account control is a serious omission.

## Minor Observations

- Every route uses the same browser title, reducing orientation across research tabs.
- Login and registration are English-only and use `noValidate` without visible password guidance.
- Chat has global header branding, sidebar branding, and topbar identity; the third layer is somewhat redundant.
- Language selection exists in chat but not auth, Documents, or Admin.
- Admin raw status labels do not distinguish queued, running, completed, and failed states visually.
- There is no skip-to-content link.

## Questions to Consider

1. If the first-minute goal is answer plus evidence, does Home earn an extra click, or should `/chat` be the real landing surface?
2. Is Documents intentionally registered-user-only, or should guests be able to search publications before signing in?
3. Are Indonesian and English both first-class experiences? If yes, should the global shell switch every route together?
4. Should Home show a real evidence excerpt instead of a generic three-step explanation?
